# KluCode — Visual Identity

Files live in `logo/`. Tokens live in `tokens/`. Everything in `logo/` is
generated by `logo/_build/build_logos.py` — **never hand-edit an SVG**; change
the script's constants and re-run, so all seventeen files stay in lockstep.

---

## 1. The idea behind the mark

```
</K>
```

Two ideas, one shape.

**The angle brackets** say *code*, immediately and in any culture. Using the
closing form `</` rather than the usual `<>` is deliberate: a closing tag is what
you write when a thing is **finished**. That is the promise the whole brand is
built on — projects that ship.

**The K is a graph, not a letter.** Four terminal nodes and one emphasised
central junction. Every edge either passes through or radiates from that hub.
It reads as a network, a schema, a dependency tree — and it is the visual form of
*klug*: the value is not in the nodes, it is in **knowing how they connect**.

The hub is the largest single element in the mark. That is the argument, made
geometrically.

### Two rules the drawing depends on

Both were arrived at by rendering the alternative and rejecting it; if you ever
redraw the mark, keep them:

1. **The stem is one unbroken stroke** from the top node to the bottom node. Drawn
   as two segments meeting at the hub, all four edges radiate equally and the
   shape reads as an asterisk. The letter disappears.
2. **The hub is ~1.4× a terminal node, no more.** Larger, and it stops being a
   junction and becomes a blob that swallows the letter.

is not finished, so the small-size lockup is a different drawing on purpose.

## 3. Clear space and minimum size

**Clear space** = the height of the wordmark's cap, on all four sides. Nothing —
text, image edge, page fold, another logo — enters that zone.

```
        ┌─────────────────────────────┐
        │   ← cap height of "K" →     │
        │   ┌───────────────────┐     │
        │   │  </K>  KluCode    │     │
        │   └───────────────────┘     │
        │                             │
        └─────────────────────────────┘
```

**Minimum sizes** — below these, step down to the next file:

| Asset               | Screen  | Print   |
| ------------------- | ------- | ------- |
| Horizontal lockup   | 140 px  | 35 mm   |
| Stacked lockup      | 80 px   | 20 mm   |
| Mark alone `</K>`   | 32 px   | 9 mm    |
| Node-K (favicon)    | 16 px   | 5 mm    |

## 4. Logo misuse

Never:

- recolour it outside the four supplied colour pairings;
- stretch, squash, or rotate it — it is horizontal, always;
- add a gradient, a drop shadow, a bevel, an outer glow, or a 3-D extrusion;
- re-typeset the wordmark (the supplied files are outlined paths — that is the
  point; a `<text>` element silently falls back to Arial on any machine without
  Space Grotesk, and would ship a broken brand);
- place the full-colour version on a mid-tone photograph — use `-paper` on a
  darkened crop instead;
- put the mark inside a box, badge, or circle that is not the supplied tile;
- pair it with a second logo without the full clear space between;
- change the spacing between mark and wordmark;
- use the mark as a bullet, loading spinner, or repeating pattern tile.

## 5. Colour

### The rule that matters most

> **Viridian `#40826D` is a display colour. It is not a text colour.**

Measured against the brand's own backgrounds:

| Pair                                    | Ratio     | Verdict                                        |
| --------------------------------------- | --------- | ---------------------------------------------- |
| `#40826D` on paper `#F2F4F1`            | **4.10:1** | ✗ fails AA for normal text · ✓ large text & UI |
| `#40826D` on ink `#0C1A15`              | **3.94:1** | ✗ fails AA for normal text · ✓ large text & UI |
| paper on `#40826D` (a filled button)    | **4.10:1** | ✗ **a white-on-viridian button label fails AA** |
| ink `#0C1A15` on paper                  | 16.17:1   | ✓ everywhere                                    |

So the brand green is used for: the logo, large display headings (≥ 24px bold),
rules, borders, icons, and backgrounds. **For anything a person has to read at
body size, use the darker steps:**

| Need                            | Light background      | Dark background        |
| ------------------------------- | --------------------- | ---------------------- |
| Body text                       | `stone-900` #0C1A15   | `stone-50` #F2F4F1     |
| Muted / secondary text          | `stone-600` #47564F (7.0:1) | `stone-300` #A9B5AE (8.4:1) |
| Green text, links               | `viridian-700` #2B564A (7.5:1) | `viridian-300` #82B39F (7.6:1) |
| Filled button background        | `viridian-600` #356C5B — paper label reads 5.5:1 ✓ | `viridian-400` #5C9781 with an ink label |
| Large display heading in green  | `viridian-500` #40826D ✓ | `viridian-500` ✓     |

This is not pedantry, and it is worth being precise about why.

Germany's **BFSG (Barrierefreiheitsstärkungsgesetz)** has applied since
28 June 2025. It almost certainly does **not** bind klucode.de itself: the
Kleinstunternehmen exemption covers service providers under ten people, and a
pure information and portfolio site without a sales or booking function falls
outside the law's scope regardless.

The commercial point is the other direction. **Your clients are frequently in
scope** — anyone selling or booking online, and anyone who grows past the
micro-threshold. So accessibility is not overhead for KluCode, it is a service
line and a differentiator: you can quote WCAG-conformant work with real contrast
figures while a competitor is still guessing. Building your own site to a
standard you are not obliged to meet is the cheapest possible proof that you can
meet it for them.

That is exactly why the ratios above are measured and written down rather than
eyeballed.

### The palette

**Viridian** — the brand hue. `500` is *the* colour.

`50 #EDF4F1` · `100 #D6E7DF` · `200 #AECFC1` · `300 #82B39F` · `400 #5C9781` ·
**`500 #40826D`** · `600 #356C5B` · `700 #2B564A` · `800 #214239` · `900 #182F29`

**Stone** — neutrals, every one carrying a trace of the brand hue so nothing
reads as generic grey. `50` is paper, `900` is ink.

`50 #F2F4F1` · `100 #E4E8E3` · `200 #CBD3CC` · `300 #A9B5AE` · `400 #7F8E86` ·
`500 #5E6E66` · `600 #47564F` · `700 #35423B` · `800 #22302A` · **`900 #0C1A15`**

**The alternating surface** is `viridian-50 #EDF4F1` on light, `viridian-900
#182F29` on dark. It is a whisper of the brand hue rather than a distinct
colour — and it can be that faint because every section already carries a 1px
`stone-200` rule at its boundary, so the edge is drawn by the rule and the fill
only has to supply a tint.

> **There is no warm colour in the brand palette.** An earlier version of this
> system carried a sand/beige surface. It was the only hue not derived from the
> brand, and in context it read as bolted on rather than designed in. Everything
> here is now viridian or a green-shifted neutral.

**Semantic** — interface states only, never marketing, never the logo.
success `#2B564A` · warning `#8A5A16` · danger `#8C2F26` ·
warningSurface `#F6EFE2`.

`warningSurface` is the single warm value left in the system and it is confined
to alert boxes on purpose: an alert that is not warm does not read as an alert.
It is a UI state, not a brand colour, and it never appears in marketing
material.

### Proportion

Roughly **72% paper or ink · 20% stone · 8% viridian**. The green is an accent
that lands hard *because* it is rationed. A page that is 40% green looks like a
hospital intranet.

## 6. Typography

| Role        | Typeface          | Weights   | Licence | Used for                                       |
| ----------- | ----------------- | --------- | ------- | ---------------------------------------------- |
| Display     | **Space Grotesk** | 500, 700  | OFL     | Headlines, the wordmark, numbers in stat blocks |
| Body        | **Inter**         | 400/500/600 | OFL   | All running text, UI, forms                     |
| Mono        | **JetBrains Mono**| 400, 500  | OFL     | Eyebrow labels, tags, stack lists, code          |

All three are open-source and self-hostable — which is not an aesthetic
preference but a legal one, see §6.2.

**Why these.** Space Grotesk is a geometric grotesque with enough irregularity to
be *recognisable* rather than merely neutral, and its `K` and `C` echo the mark's
geometry. Inter is the most legible German-language UI face available free —
important when your copy is full of `ä`, `ö`, `ü`, `ß` and 20-letter compounds.
JetBrains Mono in small caps-height labels is the quiet signal that a developer
built this page; it does a job no amount of copy can.

### 6.1 Type rules

- Display headings: weight 700, tracking `-0.02em`. Bold geometric faces always
  need negative tracking at large sizes.
- Body: 17px (`1.0625rem`), line-height 1.65. German runs longer than English;
  give it room.
- **Measure caps at 68 characters.** German compounds break badly in narrow
  columns.
- Mono labels: uppercase, `0.75rem`, tracking `+0.04em`. Never more than four
  words.
- Never centre a paragraph longer than two lines.
- Never justify. German hyphenation in browsers is unreliable enough that
  justified text opens rivers.
- Set `lang="de"` / `lang="en"` correctly — it drives hyphenation and screen
  reader pronunciation.

### 6.2 Fonts and the DSGVO — do not skip this

**Never embed Google Fonts from `fonts.googleapis.com`.** Doing so transmits the
visitor's IP address to Google before any consent is possible. The Landgericht
München I awarded damages for exactly this (Az. 3 O 17493/20), and it kicked off
a wave of German warning letters that specifically targeted small business sites.

The website in `web/` uses `next/font`, which downloads each face **at build
time** and serves it from your own domain. Zero third-party requests at runtime.
If you ever build a client site on WordPress or a static host, self-host the
`.woff2` files by hand and check the network tab before you go live — this is a
real and recurring source of cost for German freelancers, and getting it right is
something to tell clients about.

## 7. Layout

- **Grid:** 12 columns, 72rem max container, 48rem for reading-width pages
  (imprint, privacy, long-form).
- **Spacing:** 4px base grid, section rhythm `clamp(4rem, 2.5rem + 7vw, 8rem)`.
- **Alignment:** left, almost always. Centre only short hero blocks.
- **Whitespace is the brand.** When a layout feels wrong, the answer is nearly
  always more space, not another element.
- **Radius:** `0.25`–`0.875rem` for small controls, `1.25rem` (`rounded-glass`)
  for panels, full pills for buttons and tags. A frosted panel with a 14px
  radius reads as a cut-out rather than a pane.
- **Shadows:** only as part of the glass layer below — a soft, wide, low-opacity
  ambient shadow that separates a panel from what it floats over. Never a hard
  drop shadow, never on flat elements, never to fake depth where there is none.

### The liquid glass layer

Panels are **liquid glass** — slabs with thickness floating over an aurora wash —
not flat frosted rectangles. Three things separate the two, and all three are
required or the effect collapses back into "a white card with a shadow":

1. **A specular sweep.** A directional highlight raking across the face, as if
   one light source is hitting a curved lens.
2. **An edge refraction band.** A bright ring hugging the border — a *ring*,
   masked to a fixed inset, not a `border` — where a real lens would bend and
   concentrate light.
3. **Thickness.** Paired inset highlights top and bottom plus an interior
   shadow, so the panel has a bottom and reads as a slab rather than a hole cut
   in a sheet.

**The fill has to be low enough to transmit colour.** This is the counter-
intuitive part: at `0.66` the panels read as plain white cards, because glass
over a near-white background is white. Light fill is `0.44`, dark `0.50`, and
the blur is *lower* than flat glass would use (12px) with saturation *higher*
(1.9) — liquid glass transmits colour, it does not fog it.

**Which means the aurora is not decoration, it is a requirement.** Glass with
nothing behind it has nothing to refract. Sections that carry glass panels get
`glow`; sections that do not, do not.

| Token | Light | Dark |
| --- | --- | --- |
| `glass-fill` | `rgba(255,255,255,.44)` | `rgba(34,48,42,.50)` |
| `glass-fillStrong` | `rgba(255,255,255,.72)` | `rgba(34,48,42,.82)` |
| `glass-rim` / `rimLow` | specular edge lights | — |
| `glass-spec` / `specLow` | the face sweep | — |
| `glass-cast` / `depth` | ambient float / interior shading | — |
| `glass-blur` · `saturate` | `12px` · `1.9` | same |

**Classes**

- `.glass` — the standard panel. Radius `1.75rem`, 9px refraction band.
- `.glass-sm` — pills, tags, small buttons. 4px band, full radius. Without it
  the ring swallows the shape.
- `.glass-strong` — higher fill where a panel overlaps busy content.
- `.glass-solid` — near-opaque (92%), for long copy and form fields.

**The four rules that keep it readable**

1. Fills stay high enough that the audit passes — the number is not sacred, the
   audit is.
2. Long copy and form fields sit on `glass-solid`.
3. **The primary button is never glass.** Solid `viridian-600`. It is the one
   element whose contrast may not depend on what happens to be behind it.
4. Every panel keeps its border and rim, or it stops reading as glass.

**The chrome is an object.** The header is a floating capsule with page content
visibly flowing underneath, not a full-width bar pinned to the top edge. That
single move does more to signal the register than any amount of blur.

**Verify, do not assume.** Composited contrast is measured on *rendered pixels* —
declared CSS values lie the moment translucency is involved. Every text role
clears its WCAG threshold in both schemes, tightest 6.44:1 against a 4.5
requirement. **Re-run that audit after any change to fill opacity or aurora
strength**, because both move the number.

### The house graphic device

Where a page needs visual interest, use **the node graph** — small circles joined
by thin viridian lines, drawn from the logo's own geometry. Section dividers,
process diagrams, a faint background pattern behind the hero. It is the only
decorative element the brand owns, and it is free: it is literally the logo,
scaled.

Two ready-made textures ship with the kit:

| File                          | Use                                                     |
| ----------------------------- | ------------------------------------------------------- |
| `logo/klucode-texture-light.svg` | Behind a hero, as an OG-card backdrop, on a title slide |
| `logo/klucode-texture-dark.svg`  | Same, on ink                                            |

Both are 1600×900, deliberately sparse, and their density falls away toward the
upper right so there is always somewhere clean to put a headline. They are
**vector and seeded**: re-running the generator produces byte-identical files.
That matters — a texture that changes on every build is decoration, not a brand
asset.

**Why these are drawn rather than generated by an image model.** A raster
texture cannot carry exact hex values, cannot scale to a billboard, and cannot
be regenerated identically. The whole point of the device is that it *is* the
logo's geometry, so it has to come from the same source.

Do not introduce illustrations, 3-D renders, gradient meshes, or stock isometric
"technology" art.

## 8. Imagery

**Photography — one rule: real, or none.**

- Yes: you, in a Düsseldorf setting, natural light, working. Screens of the
  actual systems you built. The client's own premises, if they allow it.
- No: stock photos of diverse teams high-fiving. Handshakes. Glowing blue circuit
  boards. Anything with a stock watermark aesthetic. A single generic stock image
  undoes the entire "one real person, real work" position.
- Treatment: natural colour, no heavy filters, no duotone. If a photo needs to
  carry text, darken a crop of it rather than tinting it green.

**Screenshots** are your strongest image asset and you are under-using them.
Frame them on a `glass` panel with generous padding and a 1px
`stone-200` border. Blur or replace real client data — you will need this anyway
for the DSGVO.

**The one photograph the site cannot do without** is you. A one-person brand
whose About page has no face is asking for trust it has not offered. Plain
background, natural light, no suit, no crossed arms.

## 9. Motion

Functional only. The brand is calm; calm things do not bounce.

- Durations: `120ms` micro, `200ms` standard, `360ms` for anything entering.
- Easing: `cubic-bezier(0.22, 0.61, 0.36, 1)`.
- Allowed: fades, 4–8px rises on scroll-in, colour and border transitions on
  hover, focus rings.
- Not allowed: parallax, typewriter effects, counters ticking up, autoplaying
  carousels, anything that moves without being asked.
- **Everything must be wrapped in `prefers-reduced-motion: reduce`.** It costs
  one media query, it is WCAG 2.3.3, and vestibular disorders are common enough
  that this is not a theoretical user.

## 10. Applications

**Email signature** — plain text plus one small logo. No vCard image, no social
icon strip, no „Denken Sie an die Umwelt".

```
[Vorname Nachname]
KluCode — Klug gebaut.

[Telefon] · [E-Mail]
klucode.de · Düsseldorf
```

**Invoices and proposals** — horizontal logo top-left, generous margins, ink on
paper, one viridian rule under the document title. Nothing else. In Germany an
invoice must carry the mandatory §14 UStG fields; the design must never crowd
them out.

**Business card** — 85×55mm. Front: mark alone, centred, viridian on paper.
Back: name, role, phone, email, `klucode.de`, left-aligned, huge margins. Uncoated
stock, 350g+. Resist adding a QR code unless it goes somewhere genuinely useful.

**LinkedIn** — `klucode-avatar.svg` exported to 512×512 PNG as the page logo; the
banner is the OG card's composition at 1128×191. Your *personal* profile keeps
your face, not the logo — people hire people.

## 11. Regenerating everything

```bash
pip install fonttools uharfbuzz brotli
cd brand/logo/_build && python3 build_logos.py   # 14 SVGs
cd ../../tokens && python3 build_css.py          # tokens.css
```

`tokens/tokens.json` is the single source of truth for colour, type, and spacing.
The website's `tailwind.config.ts` imports it directly, so a value changed there
reaches the site with no copy-paste step.
